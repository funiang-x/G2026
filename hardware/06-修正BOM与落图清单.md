## 7. 第二轮：DRC 修复 + AFE 重排（2026-09-28 下午）

### 7.1 先说明：DRC 是怎么拿到的

嘉立创 EDA Pro 这版的 `eda.sch_Drc.check()` **只返回布尔值**（`includeVerboseError` 是 v4.2+ 才支持的），
桥接拿不到明细。所以自建了一份全工程 DRC（`_drc_all.py`）：
把**引脚端点 / 网络端口 / 导线端点**建成并查集，导线 union 两端点，**同名端口跨页合并**，
再按 EasyEDA 的规则集判定：单端网络 / 悬空引脚 / 位号重复 / 同网络多网名(短路) / 同点重复端口。

### 7.2 修前 vs 修后

| 检查项 | 修前 | 修后 |
|---|---|---|
| 悬空引脚（无 NC 标志） | **156** | **71** |
| 同点重复端口 | 10 | **0** |
| 位号重复 | 1（U1×2） | **0** |
| 同网络多网名（短路） | 0 | **0** |
| 单端网络 | 2（LCD_D0/LCD_D1） | **0** |

### 7.4 AFE 页重排（可看性）

**问题**：主信号链**一根导线都没有**（纯网名连接），且增益级 `U1B` 在参考块区（x≈760），
它的反馈网络却在 x≈2260 —— 相距 1500 单位，图上看不出这是同一级。

**改动**：
1. **搬件**：`U1B` (760,1400)→**(2300,1050)**；`R5` (2180,1150)→(2240,950)；`R6` (2260,1050)→(2300,1150)；`R7` (2300,1250)→(2140,1250)。
   （端口不能移动，所以每个件的旧端口都是「删掉→在新端点按原名重建」。）
2. **D1 换朝向**：旋转到横排，信号脚改用 **pin4（I/O3）** 那一排（靠近链路），`pin5`=VCC、`pin2`=GND。
3. **主信号链画成实线**：**26 根导线**，从 `J1` 一路贯到 `J2`：
   `J1 → D1/R1 抽头 → C1 → JP1 → U1A(+in) → U1A(out) → R3 → L1-C2-L3-C4-L5-C6-L7-C8-R4 → C9 → U1B(+in) → U1B(out) → R6/R7 反馈 → R8 → C10 → JP2 → J2`
4. **加 19 条功能分区文字**：①输入保护与端接 ②输入缓冲 ③抗混叠滤波 ④增益×4与ADC驱动 ⑤基准与偏置 ⑥测试点与断点，
   并把 fc=660k 的元件值与复算结论直接写在图上。

## 8. 第三轮：拿到真实 DRC 日志后的**根因修复**（2026-09-28 下午）

用户提供了嘉立创 EDA 自己导出的 `schDrcLog_2026-09-28.txt`（**致命错误 26 / 错误 0 / 警告 15 / 信息 270**）。
对照后发现了**根本性错误**——不是参数问题，是**连线模型用错了**。

### 8.1 根因：端口直接压在引脚上**不算连接**

我此前一直用「把网络端口原点精确放在引脚端点上」当连接手段。**EasyEDA 不认这个。**
官方技能 `easyeda-schematic-net-fanout`（上游 `github.com/easyeda/easyeda-enhanced-schematic-skill`，
嘉立创官方 org）给出的规程是：

> 端口放在**引脚端点外 10 单位**（沿引脚指向），再拉一根**短线**把引脚端点与端口连起来。
> 一个非 NC 引脚 = 一个端口 + 一根线。

日志里「发现元件引脚悬空」把**几乎所有引脚**都列了进去（连有端口的也算），正是这个原因。
**上一轮那句"AFE/PWR 虽然 0 导线但连接成立"是错的**——那只是我自己的几何模型自洽，EasyEDA 的网表里全是断的。

### 8.2 第二个根因：`sch_PrimitiveWire.create()` 漏了网名参数

签名是 `create(line, net?, color?, lineWidth?, lineType?)`。
我漏传 `net` → 26 根导线全变成 `$3Nundefined` → **26 条致命错误**（"网络名不正确，含有非法字符"），
且这些线被判为"游离网络，未连接任何引脚"。

### 8.3 修法与结果

| 动作 | 结果 |
|---|---|
| 按官方规程重做**三页全部扇出**：端口移到引脚端点外 10 单位 + 补 10 单位短线（带网名） | AFE 85 + PWR 44 + INT 93 = **222 个端口全部重做** |
| 删光 AFE 全部导线并重建（26 根主链路带网名 + 85 根端口短线） | AFE 111 根线全部带网名 |
| 清理扇出死循环产生的重复线（`U1B.OUTB` 与 `R8.1` 只隔 10 单位，端口一移就压到另一个脚上） | 340 → 111 根 |

**扇出完整性核验（新判据：引脚必须有导线）**

| 页 | 导线 | 引脚 | 端口 | 无导线引脚 | 无导线端口 |
|---|---|---|---|---|---|
| AFE | 111 | 98 | 86 | 11（J2.7~14 + D1.1/3/6，**都是故意不用的**） | 0 |
| PWR | 44 | 44 | 44 | **0** | **0** |
| INT | 94 | 153 | 93 | 60（H3 5 + J4 8 + EVK1 47，**都是故意不用的**） | 0 |

→ 剩余 71 个无导线引脚 = 之前那份 `07-无连接标志待点清单.md` 的 71 个，**一一对上**。

### 8.5 仍需处理（GUI 或后续）

1. **71 个 NC 标志** —— 见 `07-无连接标志待点清单.md`。
2. **器件标准化** —— 工具 → 器件标准化，一次点掉 3 条警告。
3. **元件「值」属性为空** —— 嘉立创的 BOM 取「值」字段，当前为空；需逐个补或在器件标准化时带出。
4. **`U1A`/`U1B`** —— 嘉立创位号规则只认「字母+数字」，`U1A` 不合规；

### 8.6 教训（写给下一次）

- **不要自己发明连接模型。** 落图前先读 `easyeda-schematic-net-fanout`（官方技能），
  它的「端口外移 10 单位 + 短线」不是审美偏好，是 **EasyEDA 判定连接的必要条件**。
- **自己的几何自洽 ≠ EDA 认可。** 我上一轮的"0 悬空端口"是拿自己的公式算自己的坐标，
  循环论证。**唯一可信的验收是 EDA 自己导出的 DRC 日志。**
- **`sch_PrimitiveWire.create` 的第二个参数（net）不能省**，否则网名变成 `$3Nundefined` → 致命错误。

## 9. NC（无连接标志）到底能不能用 API 放？—— 4 条路全试死的结论（2026-09-28）

结论：**在本机这版嘉立创 EDA Pro 上，API 放不了 NC 标志。** 下面是逐条证据。

| # | 路线 | 结果 | 证据 |
|---|---|---|---|
| 1 | `pin.setState_NoConnected(true)` | **方法不存在** | `typeof p.setState_NoConnected === "undefined"`；`getAllPins()` 与 `getAllPinsByPrimitiveId()` **两种取法都一样** |
| 2 | `eda.sch_PrimitivePin.modify(pin, {noConnected:true})` | **静默空操作** | 方法存在、不报错、返回对象——但什么都没改。**对照实验**：把 `{pinLength: 40}` 打进去，读回**还是 20**（改前/改后/复原三次读数全为 20） |
| 3 | 改文档源码 `setDocumentSource` | **NC 不落页面源码** | 页面源码原语只有 `DOCHEAD / CANVAS / COMPONENT / ATTR / TEXT / WIRE / LINE`，**没有 PIN**；全文搜 `noConnected` = 0 |
| 4 | 放库里的「非连接标识」符号 | **库里没有** | `lib_Device.search("no connect" / "非连接" / "noconnect")` 无结果（只搜到 Off-Page-Connector 等无关件） |

**根因**：`eda.sch_PrimitivePin` 这个类管的是**符号页**的引脚——
在原理图页上调 `eda.sch_PrimitivePin.getAllPrimitiveId()` 返回 **0**，
说明原理图页上没有它认的 "pin primitive"，所以拿它去 `modify` 元件引脚 = 无效。

> 注：`ISCH_PrimitiveComponentPin` 的文档明确写着「只有 `pinNumber` 和 `noConnected` 两个属性可以改」，
> 也就是说**接口设计上本来是支持的**，是本机这版**实现没跟上**（文档标 BETA）。
> 换更新版本的 EDA 客户端可能就好了——值得一试。
> `easyeda-draw` skill 的 `draw_cli.py mark-nc` 依赖路线 1，**在本机同样会失败**，别照抄。

### 9.1 后续实验：NC 存储格式**已定位**，但**写不进去**（2026-09-28 13:1x）

承蒙用户在 EVK1 pin1 手动打了一个 NC 标志，据此定位到**存储格式**：

```
{"type":"ATTR","ticket":1051,"id":"6b4385b72350bbb7"}||{
  "parentId":"00726019c8c2f9ff-e323","key":"NO_CONNECT","x":340,"y":-1130,"value":"yes","zIndex":327}
```

- `00726019c8c2f9ff` = EVK1 的元件 primitiveId；`-e323` = **引脚后缀**
- **后缀可查**：`pin.getState_PrimitiveId()` 返回 `00726019c8c2f9ff-e323`，与 parentId **完全一致**
  （抽样：pin1→e323, pin2→e167, pin5→e319, pin41→e7, pin80→e87, pin84→e340）
- `x,y` = 引脚**根部**坐标（y 取负）

#### 为什么还是写不进去

| 尝试 | 结果 |
|---|---|
| `eda.sch_PrimitiveAttribute.getAll(pinId)` | **该类在运行时 undefined**（`Cannot read properties of undefined (reading 'getAll')`）；而且它只有 `createNetLabel`，没有通用 `create` |
| `sys_FileManager.setDocumentSource(src + 新ATTR)` | 返回 **`true`**，但**实测不生效**：注入 1 条 TEXT 后 `sch_PrimitiveText.getAllPrimitiveId()` 前后**都是 0**，源码里搜不到注入内容 |

**判定**：`NO_CONNECT` 这条 ATTR 是**序列化器的输出、解析器不认**（单向）。
写回源码 → 解析时忽略 → 引脚没有 NC → 再序列化就没这条了。所以源码写回这条路**也堵死**。

#### ⚠️ 事故（须告知）

`setDocumentSource` 我试了 **3 次**，发现它**每次都会把页面里已存在的 `NO_CONNECT` 记录剥掉**——
**用户手动放在 EVK1 pin1 的那个 NC 标志因此丢失了。**

- 已确认其余内容完好：INT 页 4 件 / 93 端口 / 94 线，位号 EVK1·H3·H4·J4 齐全；AFE 页 39 件 / 112 线。
- **需要用户重新在 EVK1 pin1 补一次 NC（右键一下）。**
- **结论：`setDocumentSource` 在本机不可用于写 NC，也不要拿它做源码级批量改写。**

#### 最终结论

NC 标志在本机这版 EDA 上：**API 无法创建**（4 条 API 路 + 1 条源码路，全试死）。
只能 GUI 右键点，清单见 `07-无连接标志待点清单.md`（71 个脚）。
