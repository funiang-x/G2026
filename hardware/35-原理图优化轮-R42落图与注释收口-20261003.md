## §1 功能侧：R42 补装（O7）——预案两处都翻车了，实际走法如下

`27 §8.6` 预写的四条命令**不能照抄**，本轮踩到两个坑：

### 1.1 坑一：预案的器件 UUID 已漂移

预案写 `--uuid 4ea00010107c8363`，但**活体** R22~R41 的 deviceUuid 已是 `72b9a53b8e064184ad3626512d381c3c`
（期间某轮 replace/rebind 过）。照预案落件会与 20 只同款电阻绑定不一致。
**修法**：落图前先 `sch list --include-device-identity` 取活体身份再 place。
落完回读：R42 绑定 = `72b9a53b...`，与 R22~R41 完全一致（属性 Value=33Ω / C17634 / 0805W8F330JT5E 齐全）。

> ⚠️ `place` 回包 `ok:false`（验证超时）但**已落地**（fresh list 证实 134 器件、坐标 (1040,-50)、位号 R42）——
> 再次印证 skill 的"超时 ≠ 未落地，先新鲜回读"。

### 1.2 坑二：netport 改名**不重绑线岛网名**（本轮最重要的发现）

预案第②步是 `sch modify` 把 J5 侧端口改名 `LCD_RST`→`LCD_RST_J5`。实际：

1. `sch modify` 直接拒绝（"仅当器件类型为元件时允许修改"——netport 不在可改范围）；
2. 改走桥 `sch_PrimitiveAttribute.modify(attrPid, {value})`，**回读三重全对**（属性值/组件名/net 字段都是
   LCD_RST_J5），但 `sch connectivity` + 权威网表 + `sch check` 一致表明：**端口标记改名了，其下线岛的
   引擎网名还是 LCD_RST**，`sch check` 报 `net-marker-mismatch`（"网络标识 LCD_RST_J5 与所连导线
   LCD_RST 名称不一致"）；保存→重开→回读仍是老网。
3. **结论：EasyEDA 的网身份跟着线岛走，netport 的 Name 只是显示层；改名事后不生效，必须重建线岛。**

**最终走法**（全部 typed）：

```bash
# ① place（活体 deviceUuid！）
easyeda sch place --doc 63accad121e053cf \
  --lib 0819f05c4eef4c71ace90d822a990e87 --uuid 72b9a53b8e064184ad3626512d381c3c \
  --x 1040 --y -50 --rotation 0 --designator R42
# ② 改名走不通 ⇒ 直接断开（disconnect 连桩线带端口一起删，alsoDisconnectedPins=[] 无附带）
easyeda sch disconnect --doc 63accad121e053cf --pin J5:5
easyeda sch disconnect --doc 63accad121e053cf --pin R42:2
# ③ 重建两侧线岛（autoconnect 建岛时才绑定网名——与 R22~R41 同范式）
easyeda sch autoconnect --doc 63accad121e053cf --pin R42:1 --kind netport --net LCD_RST
easyeda sch autoconnect --doc 63accad121e053cf --pin J5:5   --kind netport --net LCD_RST_J5
easyeda sch autoconnect --doc 63accad121e053cf --pin R42:2  --kind netport --net LCD_RST_J5
# ④ 闭环：save → doc reload → fresh connectivity（LCD_RST / LCD_RST_J5 成员核对）→ sch check
```

验收：`LCD_RST={EVK1.14, R42.1}`、`LCD_RST_J5={J5.5, R42.2}`；net-marker-mismatch 消失；
R42.1 桩向左、R42.2 桩向右、J5.5 侧重建桩向左 offset=125（规划器硬拒了会交叉其它引脚的方向）；
INT check ERROR 仍 18（全为既有 EVK1 项）。
