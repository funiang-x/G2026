§2 五条「不是错、但要知道」

  1. PB2 = green_led 同时是 BOOT1
    核心板上 PB2 带 10k 下拉（保证默认从 Flash 启动）。当 LED 用没问题（BOOT0=0 时 PB2 不参与启动判定），但**不要把它拉到高电平再复位**。
  2. PA13 / PA14 = SWD，绝不能复用成 GPIO
    否则烧录/调试失联，而且症状是「探针连不上」，很容易误判成探针坏了。
  3. PC4 = VBIAS_SENSE 是只读探针
    固件不采它（不配 ADC1_IN14，那会改掉 TIM8+DMA 采集链）。「模拟轨是否在线」改由 AFE 输出帧的直流均值判。
  4. PB0 恰好是 TIM3_CH3
    背光必须恒亮、禁 PWM——PWM 谐波列全落在 10k~500kHz 分析带，是固定频率伪峰源。别在 CubeMX 里「顺手」把 PB0 配成 TIM3_CH3。
  5. 图上那些着色但无标签的脚（PB3~PB9 / PC0~PC3 / PE0~PE6 等）
    在 G2026.ioc 里没有任何配置（已逐脚 grep 确认）⇒ 与工程口径「NC-排针悬空」一致。着色只是 CubeMX 在提示「该脚有可用复用功能」。

§3 核心板排针映射（P1/P2 ↔ MCU 引脚）

你问的「核心板的引脚映射」—— 指 EVK1 符号的脚号（P1=1~40 / P2=41~80）↔ MCU 引脚。 这条工程侧已定案（hardware/04 §6.12），用的是双重证据：

  • PCB 焊盘几何：解核心板 EDA 工程文件，从 40 个 PAD 的局部坐标 + 网络名反推 —— e57（板左）pad1=PA2、pad13=PE7、pad23=PB10、pad37=AGND ⇒ e57 = P1； e56（板右）pad27=PD7、pad29=PD5 ⇒ e56 = P2。
  • 官方实物渲染图：对背面高清图做焊盘检测（4 列 20 行，行距 121.2 px）， 拟合镜像映射后逐脚目视复核 —— B01|E07 行中 B01(=P1-14) 在左孔、 E07(=P1-13) 在右孔，与丝印名左右顺序完全一致 ✅

⇒ 该映射没有搞错，且「P1 奇数脚在外侧、偶数脚在内侧」这条已落到 PCB 布局约束里。

§4 一点提醒：资料包是 VET6 版，实物是 VGT6-PRO

核心板资料包（docs/立创·梁山派·天空星…/）开头写明是 STM32F407VET6 版 （与 GD 版对比：换芯片 + C8/C9 电容贴上，其余一致），而工程实物是 VGT6-PRO。

两者都是 LQFP100、引脚完全兼容，差异只在 Flash 容量（VET6=512KB / VGT6=1MB）。 当前 board_config.h 按 1024KB 登记，固件占用约 508KB（48.5%）。 ⇒ 若实物其实是 VET6（512KB），余量会从 48% 掉到 ~1%，必须复核。 这是工程待办里挂了很久的一条（PROJECT.md 待办 6），建议上板前用 ST-Link 读一次芯片 ID 定案。
