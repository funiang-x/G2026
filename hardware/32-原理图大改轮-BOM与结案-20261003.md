## §1 BOM 供应商编号补全（本轮主成果）

### 1.1 问题

平台上**未指定 LCSC 编号**的元件，`supplierId` 会被默认成 `<MPN>.1`（不是真 C#）——
下单时要人工逐条补。`25 §8-8` 记着"**36 行**"这个问题。

### 1.2 为什么不用现成的 `sch resolve-lcsc`

它只查**工程库里的精确 MPN 匹配**：AFE 36 件里只解析出 **7 件**（29 件落 `unresolved`）。
而 `easyeda lib search` 查的是**平台器件库**（带 LCSC 字段），覆盖面大得多：
`0805W8F499JT5E` → **C17720** ✓

### 1.3 补全规则（**不猜**，三级判据）

```
① 只对 supplierId 不是真 C# 的件动手
② 按 MPN 查平台库 → 候选中**封装名必须完全一致**
③ 多个候选时：先用**数值**筛（10k vs 10kΩ 视为同值）；仍多则看**厂商料号是否全同**
   —— 全同 ⇒ 只是 LCSC 目录重复条目，取 name 不带后缀的那个（平台原始库条目）
④ 仍不唯一 ⇒ **跳过并报告**（不猜）
⑤ 每写一条都由 `sch modify` 回读验证
```

脚本：`_archive/_review4/eda/resolve_bom.py`（默认 dry-run，`--apply` 才写）。

### 1.4 结果

| 页 | 补前 | 补后 | 剩余 |
|---|---|---|---|
| AFE | 7 / 36 | **34 / 36** | `D1`(SRV05-4) · `R8`(100Ω) |
| INT | 25 / 25 | **25 / 25** | — |
| PWR | 2 / 7 | **6 / 7** | `D2`(SS34) |
| **合计** | **~34 / 68** | **65 / 68（96%）** | **3 件** |

### 1.5 剩的 3 件为什么**必须**跳过（这是规则在起作用，不是失败）

| 位号 | MPN | 跳过原因 |
|---|---|---|
| `D1` | SRV05-4 | 平台库里有 **2 个同封装候选，但封装名是 `…-BR` 与 `…-BL`（镜像）** ⇒ 贴反了引脚定义就错，**必须人工定** |
| `R8` | 0805W8F1000T5E | **3 个同封装候选**，且厂商料号不同 ⇒ 无法确定是哪个目录条目 |
| `D2` | SS34 | 实例封装 `SMA_L4.3-W2.6-**LS5.2**-RD`，库中只有 `…**LS5.0**-RD`（**差 0.2 mm**）⇒ 按"封装必须完全一致"跳过 |

> **这三条正是"确定性解析"的价值**：`sch resolve-lcsc` 的文档里举过一个反例
> ——"一个 U.FL 天线座被解析成 C1017 铁氧体磁珠"。**宁可留 3 条空的，也不要 3 条错的。**

### 1.6 怎么把剩下 3 条补完（人工，5 分钟）

在 EDA 里选中 `D1`/`R8`/`D2` → 属性面板 → 指定 LCSC 编号；
或把这 3 个 MPN 补进 `standard-parts.json` 再跑一次 `sch resolve-lcsc --apply`。

## §3 INT 的 18 条 `wire-through-body`：**本轮结案**（不是待办）

### 3.1 逐条看清了

```
ERROR  wire-through-body  EVK1  wire segment 0 (510,435)→(540,435) enters component body
ERROR  wire-through-body  EVK1  wire segment 0 (540,505)→(510,505) enters component body
… 共 18 条，全是 **30 单位长的引脚桩线**：
  左列引脚在 x=510（朝右）、右列在 x=1040（朝左）
```

### 3.2 根因

**EVK1 符号的 body 是"并集框"**（`18 §R-21`）：符号里有两个矩形，
`getPrimitivesBBox()` 取并集 ⇒ 框把**内侧引脚列**也包进去了。
于是**任何从内排引脚引出的线**都会被判"穿体"——**而线本身画得是对的**
（从引脚出发、30 单位到网络旗，是标准画法）。

### 3.3 为什么不能靠"改线"绕过

- 把线改到引脚**外侧**（左列往左、右列往右）技术上可行，但引脚朝向是"朝内"的，
  改完会立刻触发另一类错误 `pin-exit-direction`（`18 §3.3` 记过 AFE/PWR 各有 5/7 条这类）
  —— **换一个错误类型，没有净收益**；
- 根治只能**换 EVK1 符号**：`20` 记着上次 `sch replace` **第 3 次挂起**、靠原文恢复 ⇒ **风险 > 收益**。

### 3.4 判据

- **EDA 原生 DRC（唯一权威验收）：0 致命 / 0 错误** ✓
- `wire-through-body` 是**重建检查器**的绘图规范判据（工具自定），**不影响网表**（`18 §3.3` 明确写过）
- ⇒ **结案：接受**。已在 `18 §R-21`、`20`、`29` 三处登记。
