**⚠️ 两条必须记住的教训（都踩到了）**

1. **`dangling-wire` / "孤儿 stub" 的 finding 不能作为删除依据**。PWR 页两条被检查器判为"一端连引脚、另一端游离"的导线，**其实是 `+5V`（D2.K↔+5V 旗）与 `+5V_RAW`（J3.1↔D2.2）的承力线**——按 finding 删掉后 `+5V_RAW` 整张网消失、3 个引脚悬空（§18 记录了抢修过程）。
   **正确判据**：删任何线之前先看**原生网表成员**（`.enet` 里那两个脚在不在网上），并优先用 `sch disconnect`（线+旗一起删）；删完立刻 `sch connectivity` 对账。
2. **改完必须做"保存 → 关页重开 → 回读"闭环**（`sch save` → `doc reload` → 重读网表）。§3.4 这条 P0 本身就是"改了没落盘"的产物。

**教训（进坑册，最高优先级）**

1. **`setDocumentSource`/`getDocumentSource` 无 `--doc` 保护**（作用于"当前聚焦页"）——密集切页与多条链路交替操作后，"聚焦页"可能≠预期页。**写回前必须**：显式 `doc switch` + `project doc` 确认 + **先存"目标页现有源"作保险副本**；**写回后必须**：`getDocumentSource` 复核**关键标志**（如 `hasU1`），不能只看 `set:"true"`。
2. **`same:false` + 回读长度异常 = "写错目标"的红灯**：v5b 时 `len2=158,622` vs 写入 `158,440` 被误判为"序列化差异"并放行——**那是最早的异常信号，当时追查即可避免覆盖 AFE**。
3. **typed（list/check/text-list）与桥（getDocumentSource）的页路由可能不一致**（同一 uuid 读出不同内容）——**发现矛盾时，以"页源码 + 器件/文字/框三重交叉"判真身**，不以任一单命令为准。
4. 覆盖事故的**检测模板**（可复用）：渲染画面与 `list` 器件集不符 → 拉源 → `_dump_page.py`（TEXT/RECT/COMPONENT 三联）比对坐标族 → 定性。
