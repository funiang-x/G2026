## §2 现状分析 · 硬件

### 2.1 架构与预算现状

信号链（`02-architecture.md` §3，定案 v3）：

```
BNC ─ TVS(≤5pF) ─ 50Ω端接(1%) ─ AC耦合100nF/10k ─► BUF1(OPA2197A, G=1) ─ 50Ω串阻
     ─► LC 8阶BW fc=800k(50Ω双端接) ─ 50Ω负载 ─ AC耦合 ─► GAIN(OPA2197B, ×4, 偏置1.65V)
     ─► 100Ω+470pF ─► ADC1(PA1, fs=2.0MSPS)
```

- 底板 BOM ≈¥15（不含屏/核心板，`01 §2`）；核心板 = 立创天空星 F407VGT6 高配版。
- 电源树：5V 单路入 → 核心板自供 MCU / AMS1117-3.3 供数字 / 模拟 5V 供运放+基准；背光走 5V 恒亮。
- 误差预算（软件文档 §10）：RSS ≈ **1.31mV**，对 5mV 判据余量 **≈3.8×**；留给硬件非理想项仅 **~1mV**。

## §3 现状分析 · 软件

### 3.1 架构现状

- 四层：`Task`（调度）→ `Operation`（纯逻辑，PC 可测）→ `Device`（唯一碰 HAL）→ `Core/Drivers`；`Common` 横切。
- 实机模型：**单任务 10ms 轮询态机**（`app_rtos_run()` → `app_poll()` → `app_engine_poll()` / `app_ui_poll()` / `app_lvgl_poll()`）。engine 的 DSP 全链**拆两拍**（FFT 拍 ~8ms + 精化拍 ~5ms），保 LVGL 稳定在 60fps 上限。
- 算法层全部落地并 PC 单测绿；`MeasResult_t` 为 ≤64B 单例直读（seq 判新旧，无锁）。

### 11.3 H9 双帧变频：**裁定不做**（量化理由）

| 项 | 数字 / 事实 |
|---|---|
| 声称收益 | 残留 1.31mV → ~0.1mV，余量 3.8× → 30× |
| **实际收益** | **≈0**。① 镜像残留实测只有 **0.652mV**（输入端），对 5mV 判据余量 **7.6×**，本来就达标；② "镜像落点无真分量"的情形，**固定 1.5mV 门限已完全剔除**（S5~S8/S10~S12 实测 \|ΔUpp\| ≤ 0.016mV）；③ "镜像恰落在真分量上"（S9）**同频无法用频率分离**，只能靠幅值启发式（取两帧较小者），而镜像可加可减 ⇒ **启发式不成立** |
| 代价 | 冻结的 DSP 链要改（§5/§6 重写 + `verify_dsp.py` 全重跑）；采集 2×（~30ms，仍 ≪2s）；+8KB RAM；新增跨帧匹配的失效模式 |
| **触发条件**（若将来要做） | **只有**板到手扫频标定后实测混叠残留 > 1.5mV 门限（即 LC 实际衰减差于 −42dB）才值得做；否则优先走**硬件** Plan B（Cauer） |

> **一句话**：H9 治的是"前端不达标"的病，但**药在硬件**（Plan B / 把 LC 做好）。
> 同样一笔投入，本轮在**软件侧**改掉的 Upp 重建格点误差（−1.75mV）比 H9 的全部收益还大。

### 11.4 本轮明确未做（诚实标注）

- **采集侧乒乓双缓冲**：门控采集下生产者 2.048ms/帧 vs 消费者 DSP ~13ms/帧（快 6 倍），
  双缓冲只会让新帧盖掉未处理完的旧帧 —— **无收益**（理由已写进 `app_engine.h`）。
- **SB7 已完成**（S5~S12 已补）；**SB8 LVGL DMA 化 / SB10 `app_ui.c` 拆分**：按 §6 P2 缓做。
- **A 的上板读数**：AI 不烧录（工作台铁律 2），需人上板跑 ≥10s 后看 RTT 的 `[STACK]` 行。
