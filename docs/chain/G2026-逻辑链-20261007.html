H01 · 被测信号源 → 连接器输入与保护 · Analog · #b4530a
是什么把被测信号源以 50Ω 同轴接到板上
为什么50Ω 是仪器与同轴的标准阻抗。不统一阻抗就会有反射，幅值读数会随电缆长度变
怎么做J1 是 SMA-KE 座，屏蔽壳 4 个脚全接 AGND；芯线进 $3N702
关键数字50Ω 特性阻抗；源端 EMF 就是被测的 u_a / u_b
边界假定源是 50Ω 输出。若源设成 High-Z（高阻），端接网络的分压比就变了
失效屏蔽没接地 ⇒ 引入共模干扰，频谱上出现 50Hz 及其谐波
H02 · 50Ω 端接（对 AGND）输入与保护 · Analog · #b4530a
是什么R1 49.9Ω 从信号节点到 AGND，把源阻抗配平
为什么这是整条链第一个 ×0.5 —— 与源的 50Ω 构成分压。不端接则电缆上有反射，且源看到的负载不是 50Ω
怎么做R1 并在 $3N702 与 AGND 之间；D1 也挂在这个节点做 ESD
关键数字49.9Ω（E96，比 50Ω 少 0.2%）；分压 ×0.5
边界只在源为 50Ω 时成立。它是 BOARD_NET_GAIN = 2 里两个 ×0.5 的第一个
失效R1 开路 ⇒ 幅度翻倍；标定表会把整条链的错误吸收掉，但 ADC 可能削顶
H03 · ESD 钳位（对 AGND）输入与保护 · Analog · #b4530a
是什么D1 PESD5V0X1BT 把外部静电 / 过压钳到安全范围
为什么J1 是直接对外的接口，人体静电可达 kV 级；没有它首当其冲的是 U1A
怎么做pin1 接信号、pin3 接 AGND、pin2 悬空（单线 ESD 的常态）
关键数字钳位电压 ~9V；结电容 1.5pF（对 500kHz 信号可忽略）
边界结电容到 1.2MHz 以上才开始有分流作用 —— 仿真按 1.5pF 建模
失效pin2 若实际不是 NC 而漏焊 ⇒ DRC 每次报；器件装反 ⇒ 直接短路信号到地
H04 · AC 耦合（断直流路径）输入与保护 · Analog · #b4530a
是什么C1 100nF 隔掉直流，只让交流过
为什么被测信号是纯交流，而 U1A 的 + 端已被 R2 拉到 VBIAS=1.65V。不隔直，外部直流会和 VBIAS 打架
怎么做C1 串在 $3N702 与 $3N700 之间（1206 封装，耐压余量足）
关键数字100nF；与 R2 10k 构成高通 fc ≈ 159Hz（远低于分析带下限 10kHz）
边界高通拐点必须远低于 10kHz —— 159Hz 有 60× 余量
失效容值偏小 ⇒ 低频段幅值偏低；用有极性电容且接反 ⇒ 长期漏电
H05 · 断点 → 缓冲（+ 端经 R2 拉 VBIAS）缓冲与阻尼 · Analog · #b4530a
是什么JP1（0Ω）后接 U1A 电压跟随器，+ 端经 R2 10k 拉到 VBIAS
为什么给 LC 梯形一个确定的源阻抗（运放输出阻抗≈0，加 R3 成 50Ω）；同时把高阻输入与后面的无源网络隔开
怎么做U1A 输出直接短接反相端（单位增益）；R2 提供直流偏置通路
关键数字偏置 1.650V（= VREF/2）；R2 10kΩ；跟随器带宽 ≈10MHz（GBW）
边界偏置的戴维南阻抗 = R9//R10//R2//R5//R7 —— AC 阻抗，不是直流建立时间常数
失效JP1 未装 ⇒ 整条模拟链断开，ADC 只读到 VBIAS 直流（自检报"模拟轨可疑"其实是断点）
H06 · 源端阻尼（给 LC 定源阻抗）缓冲与阻尼 · Analog · #b4530a
是什么R3 49.9Ω 串在缓冲输出与 LC 之间
为什么LC 梯形是双端接设计（源 50Ω + 负载 50Ω）。没有 R3，源阻抗近似 0，通带会严重峰起
怎么做R3 串在 $3N701 与 $3N526 之间
关键数字49.9Ω；与 R4 一起构成梯形的两端匹配
边界与 R4 成对存在 —— 改一个必须改另一个，否则原型不再是 Butterworth
失效R3 短路 ⇒ 通带大幅峰起，500kHz 处幅值严重偏高
H07 · LC 低通 ①8 阶 LC 滤波 · Analog · #b4530a
是什么L1 4.7µH + C2 6.2nF，8 阶 LC 低通的第一节
为什么抗混叠的主力。ADC 以 2MHz 采样，1MHz 以上必须压下去，否则折叠回分析带内
怎么做8 阶双端接 Butterworth 原型（g_k = 2sin((2k−1)π/16)），R0 = 50Ω
关键数字本节谐振 ≈ 932kHz；整链 1MHz 处 −27.8dB、折叠带最差 −57.4dB
边界C2 实测值 6.2nF 比原型 5.49nF 高 +12.9%（有更近的 E24 值 5.6nF）
失效L1 开路 ⇒ 链断，读数恒 0
H08 · LC 低通 ②8 阶 LC 滤波 · Analog · #b4530a
是什么L3 22µH + C4 10nF，第二节
为什么单节 LC 只有 12dB/oct，四节串起来才够 48dB/oct 把 1MHz 压到 −28dB
怎么做与前后节串联，每节的电容都到 AGND
关键数字本节谐振 ≈ 339kHz；L3 实测 22µH 比原型 20.54µH 高 +7.1%
边界C4 是唯一已是 E24 最近值的一颗（偏差 +3.2%）
失效电容装错量级（如 10nF 装成 10µF）⇒ 通带塌陷
H09 · LC 低通 ③8 阶 LC 滤波 · Analog · #b4530a
是什么L5 22µH + C6 9.1nF，第三节
为什么与 ② 对称的中间两节 —— 8 阶原型的中间元件值最大，决定带边陡度
怎么做同上
关键数字本节谐振 ≈ 356kHz；C6 实测 9.1nF 比原型 8.22nF 高 +10.8%
边界与 C2 是"电容择优"那一轮里被优化过的两颗（标定残差 0.0299→0.0102dB）
失效同 ②
H10 · LC 低通 ④（TP3 测试点）8 阶 LC 滤波 · Analog · #b4530a
是什么L7 12µH + C8 1.8nF，第四节；TP3 是测点
为什么末节把最后的残余高频压掉，并把输出呈现给 50Ω 负载
怎么做同前三节
关键数字本节谐振 ≈ 1.083MHz；L7 实测 12µH 比原型 13.72µH 低 −12.6%（整链偏差最大的一颗）
边界TP3 可直接量这一节的频响，是唯一能上板验 LC 形状的点
失效同 ②
H11 · DC 阻断 + 50Ω 负载端接8 阶 LC 滤波 · Analog · #b4530a
是什么C7 10µF 隔直 + R4 49.9Ω 到 AGND
为什么R4 是梯形另一端的 50Ω 端接（双端接的另一半）；C7 让 R4 只对交流呈现 50Ω，不把直流通路带进来
怎么做C7 串在 $3N686 与 $3N687；R4 从 $3N687 到 AGND
关键数字10µF 对 10kHz 的阻抗 1.6Ω（vs 50Ω 可忽略）；高通拐点 ≈0.32Hz
边界⚠️ C7 的 Value(10µF) 与 MPN(CC0805KRX7R9BB104=100nF) 矛盾 —— 会订错料
失效R4 缺失 ⇒ 梯形变单端接，通带形状全变
H12 · AC 耦合增益与抗混叠 · Analog · #b4530a
是什么C9 100nF 把 LC 输出耦合到 U1B 的 + 端
为什么LC 输出直流为 0V（R4 接地），而 U1B 的 + 端要偏置在 VBIAS=1.65V —— 必须隔开
怎么做C9 串在 $3N686 与 $3N682；R5 10k 从 $3N682 到 VBIAS
关键数字100nF；与 R5 10k 的高通拐点 ≈159Hz
边界与 H04 的 C1 成对 —— 两级隔直，任一级容值偏小都会压低低频段
失效C9 开路 ⇒ U1B 只看到 VBIAS 直流，读数恒为 0
H13 · 同相放大（参考 VBIAS）增益与抗混叠 · Analog · #b4530a
是什么U1B 把 LC 出来的信号放大 7.9748 倍，参考点是 VBIAS 而不是地
为什么前面端接与 LC 双端接各损失一半（×0.5×0.5=0.25），要补回净增益 2；R7 接 VBIAS 而不是地，是为了让输出直流自动落在 ADC 的半量程
怎么做R6 24.9k 从输出到反相端，R7 3.57k 从反相端到 VBIAS；增益 = 1 + R6/R7
关键数字×7.9748；闭环带宽 = GBW/gain = 1.254MHz；500kHz 处 +0.18dB / −22°
边界绝对阻值由 H2 改图从 69.8k/10k 改成 24.9k/3.57k（比值不变）——目的是降 R7 热噪声（ADC 端噪声第一大项，√R7 律）
失效R7 接地 ⇒ 直流增益也是 ×7.97 ⇒ 输出 13.16V 贴轨（tools/sim/dc_bias_check.py 专门验过这条）
H14 · RC 抗混叠（TP4 测试点）增益与抗混叠 · Analog · #b4530a
是什么R11 100Ω + C10 470pF 到 AGND，一级 RC 低通；TP4 是测点
为什么LC 在高频已衰减，但仍需一级就近的 RC 磨平陡沿，并给 ADC 采样保持提供低阻源
怎么做R11 串在 U1B 输出与 $3N656 之间；C10 从 $3N656 到 AGND
关键数字fc = 1/(2π·100·470p) ≈ 3.39MHz；与 LC 一起把折叠带压到 −57.4dB
边界R11 也是运放的隔离电阻 —— 直接带容性负载会引起振荡，100Ω 保证相位余量
失效C10 缺失 ⇒ 高频折叠余量下降；R11 过大 ⇒ 与 ADC 采样电容构成建立不足
H15 · 断点（AFE ↔ ADC 可断开）进 ADC · Analog · #b4530a
是什么JP2（0Ω）把 AFE 输出接到 AFE_ADC_IN
为什么这是 AFE 与 ADC 之间的唯一可断开点 —— 台面上没有 AFE 硬件时，断开它可让 ADC 单独自检
怎么做JP2 串在 $3N656 与 AFE_ADC_IN 之间
关键数字0Ω
边界断开后 ADC 只读到 VBIAS 直流 ⇒ 自检报"模拟轨可疑"是预期行为，不是故障
失效把它当成故障 ⇒ 白查半天（bsp_adc.c 的自检注释专门点名这条）
H16 · 核心板排针 → MCU 引脚进 ADC · Analog · #b4530a
是什么核心板排针 EVK1.4 把信号送进 MCU 的 PA1
为什么底板与核心板之间只有排针；PA1 是 ADC1_IN1
怎么做INT 页网表 AFE_ADC_IN = EVK1.4；board_config.h 的 BOARD_ADC_IN_PIN = 1
关键数字EVK1.4 = PA1；两个来源（网表 + 宏）已交叉核对
边界⚠️ 2026-09-28 从 PA0 挪到 PA1 —— PA0 上挂着 SW2 的按键电路（10k 下拉 + 触点），对模拟前端是多余的并联负载
失效接错脚 ⇒ 采到别的通道；PA0 若仍配成模拟输入 ⇒ 按键按下会改变读数
H17 · ADC 采样网络（采样保持）进 ADC · Analog · #b4530a
是什么MCU 内部的采样开关 + 采样电容，决定"孔径"与建立时间
为什么采样保持不是理想的 —— 它要在 3 个 ADCCLK 内把外部源充到 0.5LSB 以内，这决定了前级允许的最小源阻抗
怎么做Rsw ≈ 2.2kΩ 串 + Cadc = 4pF 到地（由 t_s = 3 ADCCLK = 83.3ns 满足 0.5LSB 反解）
关键数字3 ADCCLK = 83.3ns；ADCCLK = 36MHz；转换 15 ADCCLK = 416.67ns < 500ns
边界ADCCLK 必须 ≥30MHz 且 ≤36MHz —— 这正是 SYSCLK 必须 144MHz（而非 168MHz）的原因
失效源阻抗过大 ⇒ 采样电容充不满 ⇒ 幅值系统性偏低（且随频率变化）

S01 · 复位 → 配时钟树（PLL M4/N144/P2/Q6）起机 · Init · #5a6675
人话将 8MHz HSE 经 PLL 倍频至 144MHz —— 该值由「ADC 2MSPS ⇒ ADCCLK 36MHz ⇒ PCLK2 72MHz」逐级反推得出，是唯一解
是什么SystemClock_Config() 配 PLL，把 8MHz HSE 变成 144MHz SYSCLK
为什么144MHz 不是偏好，是唯一解 —— 2.0MSPS 要求 ADCCLK=36MHz，要求 PCLK2=72MHz，要求 SYSCLK=144MHz。168MHz 下 PCLK2=84MHz：÷2 超 36MHz 上限、÷4 只有 21MHz，无解
怎么做PLL M=4 / N=144 / P=2 / Q=6；AHB ÷1、APB1 ÷4、APB2 ÷2；Flash 等待 5 周期
关键数字SYSCLK 144 · AHB 144 · APB1 36 · APB2 72 · ADCCLK 36 · TIM8 144（MHz）
边界改晶振或 PLL 必须同时改 board_config.h 与 .ioc，否则 fw.py lint 报确定性矛盾
失效时钟配错 ⇒ HAL 时基失准、所有延时与波特率全错；fw.py lint 是唯一的自动拦截
S02 · CubeMX 初始化全部外设起机 · Init · #5a6675
人话按 .ioc 单一配置源依次初始化 GPIO / DMA / SPI1 / RTC / TIM8 / I2C2 / ADC1 / FSMC
是什么MX__Init() 把 GPIO/DMA/SPI1/RTC/TIM8/I2C2/ADC1/FSMC 配好
为什么外设配置一律走 GUI 生成 —— 手改寄存器没有单一真相源；.ioc 是唯一来源
怎么做main() 里顺序调用；每个 MX__Init 的引脚与时钟来自 .ioc
关键数字FSMC AS=2 / DS=12；TIM8 PSC=0/ARR=71；ADC1 触发 TIM8_TRGO + DMA 连续请求
边界⚠️ 注释与 .ioc 冲突时以 .ioc 为准 —— 四处文档写"DS=85"但从未落地
失效初始化失败走 Error_Handler；若它调 app_panic ⇒ 整板不启动（曾因没插 TF 卡触发）
S03 · 组合根 app_init()：Device 就位 + Operation 注入 + 引擎/UI 初始化起机 · Init · #5a6675
人话完成系统装配：初始化 Device 层实例 → 向 Operation 层注入参数 → 初始化引擎与 UI；执行于调度器启动之前
是什么app_init() —— 全工程唯一的应用入口，做三件事：创建实例 → 注入参数 → 启动
为什么它是四层结构里唯一允许跨层的地方（同时看 Device 与 Operation）；其余文件只向下调
怎么做bsp_log_init → bsp_tick_init → bsp_adc_init → app_lvgl_init → app_engine_init → app_ui_init → app_self_test
关键数字运行在调度器启动前 ⇒ 不许取任何 FreeRTOS 原语
边界建内核对象后必须 portENABLE_INTERRUPTS() —— 否则 BASEPRI 被钉住、HAL_Delay() 死循环
失效顺序颠倒（如 app_ui_init 早于 app_engine_init）⇒ UI 读不到"已标定"状态
S04 · app_self_test() 十项自检起机 · Init · #5a6675
人话上电后逐项探测板载外设，结果记录至 RTT 日志；任何一项失败都不作为启动门槛
是什么app_self_test() 逐项探测板载外设，结果写入 RTT 日志
为什么"编译通过 ≠ 能跑" —— 符号入库证明不了 Flash 读得出 JEDEC ID、屏读得到 ID
怎么做十项各自独立：SPI Flash / 时钟 / RTC / 读写往返 / LCD RDDID / 触摸 / DSP 链 …
关键数字任何一项失败都不停机
边界教训：SDIO 曾因没插卡让整板起不来（Error_Handler → app_panic）
失效把某一项当启动门槛 ⇒ 可选外设绑架启动
S05 · app_rtos_run()：建两任务 → 等 VBIAS → 采样链自检起机 · Init · #5a6675
人话创建 Engine / Ui 两个任务，等待模拟偏置 VBIAS 建立（≥129.5ms）后再执行采样自检
是什么app_rtos_run() 建 Task_Engine(26) / Task_Ui(23)，等 VBIAS 建立后跑采样自检
为什么VBIAS 要充电到稳定 —— 不等就采，帧直流均值偏出半量程带，会报假的"模拟轨可疑"
怎么做xTaskCreateStatic ×2（栈与 TCB 是静态数组，不动 15KB 的 FreeRTOS 堆）；osDelay(200)
关键数字直流戴维南 = R9//R10 = 5.0kΩ ⇒ τ=50ms ⇒ 到 92.5% 需 129.5ms
边界改前靠 bsp_lcd_init 的 140ms 延时侥幸盖住 —— 那是屏的时序需求，不是 AFE 的依赖
失效不等 ⇒ 报假告警，把人往"查地 / 查 JP2"的错方向带
S06 · 测量任务等"周期到"或"UI 请求重测"采集 · Engine · #1a5fb4
人话测量任务单次阻塞等待"500ms 周期超时"与"UI 重测请求"两类事件，任一到达即执行一帧测量
是什么测量任务用 xTaskNotifyWait 等"周期到"或"UI 请求重测"
为什么把"周期超时"与"外部唤醒"合成一次阻塞调用 —— 不轮询、不多一个队列；切页即刻响应
怎么做超时 500ms；app_engine_remeasure() 用 xTaskNotifyGive 唤醒
关键数字周期 500ms ⇒ 屏上数据 ≤0.6s 旧（题面"每项 ≤2s"的 1/3）
边界退出时清空通知计数，避免多次 remeasure 攒成"连续狂测"
失效用"定时 + 轮询标志"代替 ⇒ 采集完成最多白等一拍，切页响应变慢
S07 · 抢 LCD 总线闸（采样窗静默的第一步）采集 · Engine · #1a5fb4
人话在启动采集之前取得 LCD 总线互斥量，使 FSMC 写屏在块边界停住 —— 保证 2.048ms 采样窗内总线无跳变
是什么bsp_lcd_bus_take(20ms) —— 采样窗静默的第一步
为什么写屏是板内最大干扰源（2 层板没有地平面兜底），而采样窗只有 2.048ms。闸在开采集之前拿，写屏就会在块边界停住
怎么做互斥量带优先级继承（写屏侧持闸时 engine 来抢，会让它临时提权把当前块写完）
关键数字等待上限 20ms（正常只需等一个块 ≈0.107ms）
边界拿不到 ⇒ 退化为整帧级避让，不比改前差（不是失败）
失效不拿闸 ⇒ 采样窗内 FSMC 照 toggle，最大干扰源灌进 AFE
S08 · 挂 ADC+DMA → 放 TIM8 触发采集 · Engine · #1a5fb4
人话先挂接 ADC+DMA、再使能 TIM8 触发 —— 顺序颠倒会丢失 DMA 未就绪期间的前几次采样
是什么bsp_adc_start() 挂 ADC+DMA，然后放 TIM8 触发
为什么顺序不能反 —— 先放 TIM8 的话前几次触发会丢（DMA 还没就绪）
怎么做HAL_ADC_Start_DMA（内部启动 ADON + 使能 DMA 请求 + 挂完成回调）→ HAL_TIM_Base_Start
关键数字一帧 4096 点 @2.000MHz = 2.048ms；DMA2_Stream0 循环 / 半字
边界有 CCM 落区守卫 —— buf 落在 CCM 会静默恒 0，这是唯一能拦住它的地方
失效缓冲放 CCM ⇒ 采集恒 0 且不报错（最阴险的静默失效）
S09 · 中断：搬满一帧 → 停触发源 → 给信号量采集 · ISR · #b58900
人话DMA 搬满一帧（4096 点）后在中断内停触发源、置完成标志并释放信号量；业务收尾全部留在任务上下文
是什么HAL_ADC_ConvCpltCallback —— 搬满一帧时停触发源、置标志、给信号量
为什么中断里只投事件不跑业务；真正的收尾由主上下文做（HAL_ADC_Stop_DMA 会取锁、可能阻塞）
怎么做__HAL_TIM_DISABLE(&htim8) → s_done=1 → xSemaphoreGiveFromISR → portYIELD_FROM_ISR
关键数字DMA2_Stream0 抢占优先级 = 5 = configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY ⇒ 正好允许调 FromISR 系列
边界优先级再小一号就不许调 FromISR 了
失效Circular 模式下 DMA 永不停 ⇒ 调用方必须自己 bsp_adc_stop()，否则数据被循环覆盖
S10 · 阻塞等到帧 → 停采集 → 放闸采集 · Engine · #1a5fb4
人话阻塞等待帧完成信号量，按"先停触发源、再停 DMA"的顺序关停采集，最后释放总线互斥量
是什么bsp_adc_wait_frame(50ms) 阻塞等信号量，拿到后 bsp_adc_stop() 再放闸
为什么bsp_adc_stop 的顺序是先停触发源再停搬运 —— 反过来会留下"还在转换但没人搬"的窗口，下一帧第一个点是上一帧的残留
怎么做等待期间让出 CPU；UI 任务会跑，但它在块边界拿不到闸 ⇒ 不写 FSMC
关键数字超时 50ms（正常 2.048ms，50ms 是"链断了也不永久挂死"的看门狗口径）
边界超时 ⇒ 报 W 日志并跳过本帧，不是停机
失效不设超时 ⇒ 触发链或 DMA 断了就永久挂死
S11 · 去DC + 折算 mV + BH4 加窗 + 交织 + FFT + 取模算法 · Engine · #1a5fb4
人话将 4096 个 ADC 码值折算为输入端 mV，去除直流均值（偏置非信号），加 BH4 窗后作 4096 点 FFT 得到频谱
是什么op_dsp_run() —— 去均值 → 折成输入端 mV → 乘 BH4 窗 → 交织复数 → 4096 点 FFT → 取模
为什么去 DC 是因为 VBIAS 偏置是"0 点"；加窗压泄漏（BH4 旁瓣 −92dB）；交织那一步必须显式写虚部 0，否则算的根本不是实序列谱
怎么做s_xw[4096]（SRAM1）→ op_dsp_pack_real_to_cfft → s_fft[8192]（CCM 低半区）→ arm_cfft_f32
关键数字N=4096；Δf = fs/N = 488.28125Hz；BH4 相干增益 CG = 0.35875；s_fft 必须是 2N
边界s_adc_buf/s_xw 在 SRAM1（DMA 可达 / 普通 bss），s_fft 在 CCM —— 落区一错就是静默失效
失效s_fft 只给 N ⇒ FFT 写穿 16KB 踩坏相邻数组（PC 测不到，host 走朴素 DFT 替身）
S12 · 找峰：栅格预筛 → 两级抛物线精化 → 单点 DFT算法 · Engine · #1a5fb4
人话先按 1.5mV 门限做栅格预筛，再以两级抛物线插值将频率估计细化到 488Hz FFT 栅格分辨率以下
是什么op_peak_run() —— 栅格预筛 → log 域三点抛物线 → ±Δf/8 三点 \
为什么FFT 栅格只有 488Hz，题面要的分辨率不够；两次抛物线精化把频率推到栅格以下。幅值不在栅格上直读，而是在精化后的频率上做单点 DFT（口径①）
怎么做预筛门限 1.5mV 挡伪峰；单点 DFT 用 Kahan 补偿累加 + 每 256 步重置旋转因子（误差不跨步累积）
关键数字扫带 [9000, 502000]Hz；门限 1.5mV
边界k_lo = (int)(f_lo/df) 且搜索从 k_lo+1 起 ⇒ 写 10000 会整个漏掉 10kHz 的峰；循环止于 k_hi−4 ⇒ 写 500000 会漏掉 500kHz
失效门限太低 ⇒ 量化噪声伪峰被当真线；只做预筛不做终判 ⇒ 精化后掉下门限的假线混进来
S13 · 标定修正（幅值 / 相位）算法 · Engine · #1a5fb4
人话以 17 点对数间隔标定表（存于 W25Q128）修正幅值与相位的频率响应误差，得到被测真实值
是什么op_cal_lookup() 用 17 点表修正幅值与相位（amp/=g、φ−=p、再 φ+=π/2）
为什么AFE 是 LTI 系统 —— 幅频相频的所有误差（端接分压、LC 形状、运放滚降、孔径效应）都能被"赛前一次标定"吃掉
怎么做表存 W25Q128 扇区 0（216B，magic+CRC）；g 与 p 都在 log-f 域插值
关键数字17 点对数间隔 10k→500k；修后 Upp 残差 ≤0.25mV（判据 ±5mV）
边界相位必须在建表时展开（unwrap） —— AFE 相移在 306.6~391.6kHz 穿过 ±180°，不展开该区间会插出 179.5° 的错
失效不展开 ⇒ 160kHz 基波 + 二次谐波时 Upp 偏 −18.95mV（判据的 3.8 倍）；且仿真会把它藏住（s8_e2e_fw.py 用了 np.unwrap）
S14 · 四口径（f1 / Upp / Urms）算法 · Engine · #1a5fb4
人话由各分量幅值与相位重建时域波形，取基频 f1、峰峰值 Upp 与有效值 Urms 三个口径
是什么op_meas_build() —— f1（最低峰）、Urms = √(ΣA²/2)、Upp = sin 重建取 max−min
为什么题面要 Upp（峰值），而频谱只给分量幅值 —— 必须按级次与相位把波形重建出来才能取 max−min
怎么做级次 m_k = round(f_k/f1)；重建点数按最高阶次自适应 max(512, 32·m_max)
关键数字固定 512 点在 m_max=50 时只有 10.2 点/周期 ⇒ Upp 偏 −1.75mV（判据的 35%）
边界重建用的是各分量源端口径的相位 ⇒ S13 的相位修正直接决定它准不准
失效点数不足 ⇒ 大阶次信号 Upp 系统性偏低（是偏差不是噪声）
S15 · 发布结果（覆盖式 mailbox）算法 · Engine · #1a5fb4
人话测量结果经单深队列覆盖式发布：engine 只写、UI 只读，队列临界区保证不会读到写了一半的结构体
是什么xQueueOverwrite(s_result_q, &r) —— 1 深队列的覆盖式发布
为什么engine 只写、UI 只读；队列自带临界区 ⇒ UI 永远读不到"写了一半"的结构。覆盖式 = 不阻塞、不失败
怎么做队列存储用元素类型声明（不是 uint8_t[]）—— 对齐天然正确（历史坑）
关键数字meas_result_t 56B ≤ 64B 硬约束（历史教训：4144B 局部变量爆栈）
边界结果体不含指针与波形数据 —— 波形只在 UI 层静态区生成
失效队列深度 >1 ⇒ 攒帧、UI 读到过期数据；用 xQueueSend 而非 Overwrite ⇒ 满时阻塞或丢新帧
S16 · UI 避让采集窗 → 取快照（按 seq 判新）呈现 · Ui · #0f7b6c
人话检测到采样窗（app_engine_acquiring()）时暂缓一切 FSMC 访问，随后 xQueuePeek 取快照并按 seq 判新
是什么UI 任务先避让采集窗，再 app_engine_result() 取快照（xQueuePeek），按 seq 判新
为什么app_engine_acquiring() 为 1 时不碰 FSMC —— engine 优先级更高，但 engine 阻塞在信号量上时 CPU 会回到 UI，那时必须主动避让
怎么做while (app_engine_acquiring()) vTaskDelay(1)；xQueuePeek 自带临界区且不消费
关键数字避让窗口 2.048ms；节拍 10ms（= LVGL 的时间分辨率）
边界seq 没变且没翻页 ⇒ 直接返回，不白刷
失效不避让 ⇒ 采样窗名存实亡；触摸读失败与"没按"若不都算抬起 ⇒ I2C 抖动变假点击
S17 · 重建波形曲线 / 谱线呈现 · Ui · #0f7b6c
人话波形与谱线重建实现为纯函数（Operation 层）：UI 只负责绘制、不做计算，因此可在 PC 上单测
是什么op_wave_build() 生成 320 点波形、op_spec_build() 生成谱线柱的 x01/len01
为什么UI 只该画、不该算 —— 重建是纯逻辑，放 Operation 层就能在 PC 上单测
怎么做op_wave_build(r, cycles, y, 320)；cycles 支持 1T / 3T 切换（点波形页）
关键数字320 = 屏宽 1:1（每像素一列，无插值观感）；320×3 分量 sinf ≈ 1ms 级
边界重建在 UI 刷新时跑，不能在中断里做
失效把重建塞进 op_meas ⇒ 结果体超 64B、栈爆
S18 · LVGL 脏区重绘呈现 · Ui · #0f7b6c
人话推进 LVGL 时基并执行脏区重绘：只重画变化区域，不做整屏刷新
是什么app_lvgl_poll() 推进时基 → lv_timer_handler() 跑脏区重绘
为什么LVGL 的时间分辨率就是这个循环的节拍（10ms）—— 改成 >16ms 会掉帧
怎么做lv_tick_inc(dt) 用两次调用的差值推进；第一次只记时间不推（否则把开机那几秒当成一次 tick）
关键数字draw buffer 320×48×2 = 30.7KB @SRAM1；LVGL 池 32KB @CCM 高半区
边界draw buffer 不能放 CCM（将来若改 DMA 搬 FSMC 会静默失效）
失效漏了 lv_display_flush_ready() ⇒ 界面永久卡死（实测现象：屏上只有一条 48 行白带）
S19 · 分块写 FSMC → 屏出现数字呈现 · Ui · #0f7b6c
人话渲染完成的像素按块写入 FSMC；每块写入前取得总线互斥量，使采样窗可以在块边界插入
是什么lcd_send_color 分块写 → bsp_lcd_write_pixels 把 16 位字写进 0x60020000
为什么命令与数据只差一个地址（RS 接在 FSMC_A16 上）⇒ 不用翻引脚，CPU 只管 store
怎么做每 1024 px 一块、每块开写前抢闸（engine 才能在块边界把总线拿过去）
关键数字地址偏移 1<<17（16 位总线时 FSMC 把 HADDR 右移 1 位）；现行 AS=2/DS=12 ⇒ 104.2ns/字 ⇒ 整帧 16.0ms ⇒ 62.5fps
