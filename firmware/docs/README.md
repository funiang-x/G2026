## 维护

```bash
# 检查骨架里的文档引用是否都存在（改完骨架跑一下）
python Tools/fw.py doccheck
```

`check_doc_links.py` 扫**两类**引用：

1. 反引号里的路径（`` `docs/01` ``、`` `Tools/fw.py` ``）；
2. **围栏代码块内**以 `python` / `bash` / `sh` 开头、且含 `tools/` 或 `test/` 路径的命令行。

> 第 2 类是后加的（来自 `esp32_prj` 的一次真实提案）：只扫反引号时，
> "删了脚本但文档还教人跑它"这类死链**不会被发现**。

**死链是无声的** —— 没有报错，直到某次 AI 按错的路子干了活。
所以每次改骨架或改文件名，都要跑一次。

### 短引用约定

骨架里写 `docs/01` 而不是 `docs/01_工程分层架构.md` —— 这是**故意的**，
为了省骨架的行数（骨架有 ≤110 行的硬预算）。

代价：`docs/01` **不是合法路径**，肉眼看不出对错。
所以 `check_doc_links.py` 专门支持这个约定（`docs/01` 会去匹配 `docs/01*.md`），
**必须靠工具验证，不能靠肉眼**。

⚠️ 由此带来一条约束：**同编号前缀的文档不能有两个**
（否则 `docs/01` 指向哪个就不确定了）。改文件名时保持编号唯一。

### 示例路径一律用 `xxx` 占位

写示例时用 `Operation/Src/op_xxx.c`、`Device/Src/bsp_xxx.c`，
**不要**用看起来像真文件的假名字（比如某个具体模块名加 `.c`）——
`check_doc_links.py` 会把后者当死链报出来（这是**故意的**：
"看起来像真文件"的示例，人也会当成真文件去找）。

检查器认这三类占位符，一律跳过：

| 写法 | 例 |
|---|---|
| `xxx` / `yyy` / `zzz` | `Operation/Src/op_xxx.c` |
| 尖括号 | `Core/Src/<模块>.c` |
| 波浪号区间 | `docs/01~13` |

编号占位符用 `x`：`docs/0x` 会去匹配 `docs/0[0-9]*.md`。

### 必须提到不存在的名字时：整行豁免

三类场合**故意**要写不存在的名字：① 变更记录里的旧路径；② 迁移说明里的旧函数名；
③ **反例**（"别这么写"）。这些行末尾加 `<!-- doclink-ignore -->`，检查器跳过该行。

⚠️ 它只豁免**同一行**，不豁免相邻行 —— 这样"豁免标记写错地方"会当场暴露，
而不是静默地把一片问题都放过去。
⚠️ 拿它掩盖真问题 = 把门禁拆了。真死链的正确修法是改路径或补文件。
