# 06 — 数据类型规范

> 状态：**已定稿**（2026-09-21）

## 管什么

用哪些整数类型、什么时候 `typedef`、什么时候要 `volatile` / `_Atomic`。

## 整数类型

**一律用 `<stdint.h>` 的定宽类型**，不用 `int` / `short` / `long`：

| 用途 | 用 | 不用 |
|---|---|---|
| 寄存器/位掩码 | `uint32_t` | `unsigned int` |
| 引脚号、小计数 | `uint8_t` / `uint16_t` | `char` / `unsigned char` |
| 长度、索引 | `uint32_t` 或 `size_t` | `int` |
| 有符号的差值/时间差 | `int32_t` | `int` |
| 布尔 | `bool`（`<stdbool.h>`） | `uint8_t` 当布尔 |
| 浮点 | `float`（**优先**）/ `double` | — |

⚠️ **`int` 只在两种情况下允许**：① `main()` 的返回值；② 与标准库签名对齐
（如 `memcmp` 的返回值）。其它地方出现 `int` 一律改成定宽类型。

### 为什么要这么严

嵌入式里 `int` 的宽度**随编译器/平台变化**，而定宽类型不会。
更实际的原因：`-Wconversion` 类告警一旦开了，"这里该不该窄化"就会变成每次改动都要重新判断的事；
统一用定宽类型能让大部分隐式转换变成显式。

## 常量后缀

数值宏与字面量**必须带后缀**：

| 值范围 | 后缀 | 例 |
|---|---|---|
| 能用 `unsigned int` 表示 | `U` | `500U` · `115200U` |
| 超过 32 位无符号 | `UL` | `168000000UL` |
| 浮点 | `f`（用 `float`） | `0.001f` · `60.0f` |

⚠️ **浮点字面量不加 `f` 会默认是 `double`** —— 在 Cortex-M4F 上触发
`-Wdouble-promotion`（本工程开了这个告警）。所有浮点常量、所有 `float` 参与的
运算都要显式 `f`。

## `typedef` 什么时候用

| 用 | 不用 |
|---|---|
| 结构体 / 枚举：`typedef struct { ... } op_filter_t;` | `typedef uint8_t op_byte_t;`（没有信息量） |
| 回调函数指针：`typedef void (*bsp_delay_fn)(uint32_t ms);` | 给 `int` 换名字 |
| 需要跨层传递的不透明句柄 | 为了"看起来短一点" |

- 结构体用**匿名结构体 + `typedef`**，不用 `struct _foo` 这种双名写法。
- 类型名后缀统一 `_t`（见 `04`）。

## `volatile` 什么时候加

**只在两种情况下加**：

1. 变量会被**中断服务程序**修改，而主流程会读它（例：ISR 置的标志位）；
2. 指向**硬件寄存器**的指针（HAL 内部已处理，自己写寄存器时才需要）。

❌ **不要**因为"怕编译器优化"就到处加 `volatile`。它不解决并发问题，
只会让编译器放弃优化、并且掩盖真正的同步缺陷。

> 判据：`s_` 前缀的静态变量（见 `04`）是**高风险候选** —— 看到它被 ISR 写过就必须加 `volatile`。
> `-Wunused-volatile` 类问题查不出来，这条只能靠 review。

## `_Atomic` 什么时候用

`Operation/` 层需要跨上下文共享数据时，**不许用锁**（锁属于 RTOS，违反规矩 2），
用 C11 `<stdatomic.h>`：

```c
/* Operation/Inc/op_model.h —— 无锁双缓冲，纯 C11 */
#include <stdatomic.h>
typedef struct {
    _Atomic uint32_t seq;
    int16_t buf[2][OP_MODEL_LEN];
    _Atomic uint32_t idx;
} op_model_t;
```

⚠️ **代价要认：seqlock 只允许一个写者。** 加第二个写者就是改错 ——
要么合并写者，要么换方案。这条在 `Task/` 层装配时最容易破（见 `AGENTS.md` §硬规则）。

## 位操作

| 操作 | 写法 |
|---|---|
| 置位 | `reg \|= (1U << n);` |
| 清位 | `reg &= ~(1U << n);` |
| 取位 | `(reg >> n) & 1U` |
| 测试 | `if (reg & (1U << n))` |

⚠️ **位移常量必须带 `U`** —— `1 << 31` 是有符号溢出（UB），`1U << 31` 才对。
⚠️ **不要自己写寄存器位定义** —— 查 `Drivers/CMSIS/Device/ST/STM32F4xx/Include/stm32f407xx.h`
里的宏（见 `AGENTS.md` §硬规则 6）。

## 结构体初始化

**一律用 `= {0}` 显式清零**：

```c
op_filter_t ctx = {0};
UART_HandleTypeDef huart = {0};   /* HAL 的 Init 结构体字段极多 */
```

漏初始化是"偶发不工作"的头号原因 —— HAL 的 `Init` 结构体有大量字段，
少填一个不会报错，只会行为异常。
