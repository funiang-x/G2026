# 07 — 模块实现规范

> 状态：**已定稿**（2026-09-21）

## 管什么

一个模块（一对 `.h`/`.c`）内部怎么组织。

## 一个模块的骨架

```c
/* ============================================================================
 *  bsp_uart.c —— UART 收发的设备层实现
 * ==========================================================================*/
#include "bsp_uart.h"          /* 第一条必须是自己 */

/* ---------------------------------------------------------------- 私有宏 */
#define UART_RX_BUF_LEN 128U

/* ---------------------------------------------------------------- 私有类型 */
typedef enum { UART_ST_IDLE, UART_ST_RX } uart_state_t;

/* ---------------------------------------------------------------- 私有变量 */
/* s_ 前缀 = 模块级静态（见 04）。会被 ISR 碰的必须 volatile（见 06） */
static QueueHandle_t s_uart_evt_q;
static volatile uint8_t s_rx_byte;
static uint8_t s_rx_buf[UART_RX_BUF_LEN];

/* ---------------------------------------------------------------- 私有函数 */
static void uart_drain(void);

/* ---------------------------------------------------------------- 公开接口 */
int bsp_uart_init(uint32_t baud) { ... }

/* ---------------------------------------------------------------- 私有实现 */
static void uart_drain(void) { ... }

/* ---------------------------------------------------------------- 中断回调 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *h) { ... }
```

**分段顺序固定**：私有宏 → 私有类型 → 私有变量 → 私有函数原型 → 公开接口 →
私有实现 → 中断回调。

## 三条硬规定

### 1. 模块内部的一切都是 `static`

不在 `.h` 里出现的东西，在 `.c` 里必须 `static`。包括函数、变量、类型、宏。

**为什么**：`static` 把符号限制在本编译单元，是**最便宜的封装** —— 零成本、零运行时开销。
非 `static` 的模块内部符号会污染全局命名空间，并且在链接期可能撞名。

### 2. 公开函数必须有原型在 `.h` 里

`-Wmissing-prototypes` 会拦。这条的真实价值是**拦住"改了函数签名忘了改头文件"** ——
那种错在别的编译单元调用时才炸，报错点离病根很远。

### 3. 初始化函数必须幂等或显式拒绝重复调用

```c
int bsp_uart_init(uint32_t baud) {
    if (s_inited) {
        return BSP_ERR_ALREADY_INIT;   /* 或直接 return 0，二选一，写清楚 */
    }
    ...
    s_inited = true;
    return 0;
}
```

⚠️ 不写的话，重复调用会**泄漏队列 / 覆盖句柄 / 重复注册中断**，
而症状是"跑一阵子才出问题"，极难查。

## 返回值约定

| 场景 | 形式 |
|---|---|
| 只有成功/失败 | `int`，0 = 成功，负 = 错误码 |
| 需要返回数值 + 状态 | 数值通过出参指针，返回值是状态 |
| 纯计算（`Operation/` 层） | **直接返回值**，不返回状态码（纯函数不会失败） |

错误码定义在 `Common/Inc/log.h` 同目录的 `err.h`（本工程用负值 + `#define`）。

⚠️ **不要用 `bool` 当"可能失败"的返回值** —— 失败原因会丢失。
纯"是/否"判断（`bsp_uart_is_busy()`）才用 `bool`。

## 状态机怎么写

`Operation/` 层里的状态机用**显式枚举 + switch**，不要用嵌套 `if`：

```c
switch (ctx->state) {
case OP_ST_IDLE:
    if (raw > ctx->trip) { ctx->state = OP_ST_CANDIDATE; ctx->since_ms = now_ms; }
    break;
case OP_ST_CANDIDATE:
    if (raw <= ctx->clear) { ctx->state = OP_ST_IDLE; }
    else if (now_ms - ctx->since_ms >= ctx->debounce_ms) { ctx->state = OP_ST_TRIPPED; }
    break;
case OP_ST_TRIPPED:
    if (raw <= ctx->clear) { ctx->state = OP_ST_IDLE; }
    break;
}
```

- 每个状态分支**只做状态转移**，不做耗时动作。
- 动作（发日志、点亮 LED）由 `Task/` 层根据返回的状态去做。

## 周期逻辑做成显式入口

⚠️ **不要把周期逻辑直接写进任务循环体**：

```c
/* ❌ 差：实现埋在 for(;;) 里，将来拆任务要搬家 */
void app_task(void *arg) {
    for (;;) {
        uint32_t now = bsp_tick_ms();
        /* 几十行业务... */
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

/* ✅ 好：显式入口，循环体只负责"什么时候调" */
void app_uart_poll(uint32_t now_ms);   /* 在 app_uart.h 里声明 */

void app_task(void *arg) {
    for (;;) {
        app_uart_poll(bsp_tick_ms());
        vTaskDelay(pdMS_TO_TICKS(APP_TICK_PERIOD_MS));
    }
}
```

**为什么**：任务划分是最常改的东西。逻辑做成显式入口后，调整任务结构时不用搬家，
而且它能在 `Test/` 里被直接调用（前提是它不碰 RTOS）。

> 这条有历史代价：参考工程曾同时支持裸机与 RTOS 两套骨架，周期逻辑只挂在一个上时，
> 另一个构型**完全不执行**，且没有任何编译/链接告警（函数甚至被 `--gc-sections` 整个裁掉，
> 不在符号表里，极容易被误读成"库没链进来"）。

## 条件编译的使用边界

⚠️ **不要用"只在部分目标上定义"的宏做功能开关。**

```cmake
# ❌ 差：只有一部分 target 拿到 USE_FREERTOS
target_compile_definitions(device PRIVATE USE_FREERTOS)
```

后果：`#else` 分支被静默编进固件 —— 编译、链接、门禁、上板**全都看不出来**，
症状要等到特定并发场景才偶发出现。

**做法**：要么给所有需要的目标都定义，要么**干脆不用条件编译**（本工程选后者）。

> 判据：`grep -rn "if defined(" 源码` 找出所有条件编译，
> 再核对 `target_compile_definitions` 是否**每个引用它的目标**都拿到了那个宏。

## 功能开关要有闸门

一个 `#define APP_ENABLE_XXX 0` 如果没有任何代码读它，它是"孤儿宏"。
把意图写成**编译期闸门**：

```c
#define APP_ENABLE_IWDG 0
#if APP_ENABLE_IWDG
#error "APP_ENABLE_IWDG=1，但工程里没有 bsp_iwdg 实现：请先补模块再启用"
#endif
```

两个效果同时成立：① 记录了"我知道有这个需求，只是还没做"；
② 谁翻成 1 谁当场看到原因，而不是编译通过、运行无变化。
