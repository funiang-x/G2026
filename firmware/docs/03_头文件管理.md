# 03 — 头文件管理

> 状态：**已定稿**（2026-09-21）

## 管什么

include 写在哪、写什么顺序、什么时候用前置声明。

## include 顺序（固定四段，段间空一行）

```c
/* 1. 对应的自有头（.c 的第一条 include，必须是自己的 .h） */
#include "bsp_uart.h"

/* 2. C 标准库 */
#include <stdint.h>
#include <string.h>

/* 3. 本工程其它层（按依赖方向自上而下，同层按字母序） */
#include "log.h"
#include "bsp_gpio.h"

/* 4. 第三方 / HAL / FreeRTOS（只允许出现在 Device 层） */
#include "stm32f4xx_hal.h"
#include "FreeRTOS.h"
#include "queue.h"
```

`.clang-format` 的 `IncludeBlocks: Regroup` + `SortIncludes: true` 会自动排序；
上面的分段靠**空行**保留（clang-format 不跨空行合并分组）。

> ⚠️ **`.c` 的第一条 include 必须是自己对应的 `.h`。** 这不是风格问题 ——
> 它让编译器替你检查"头文件是否自洽"（缺少的 include 会在编译该 `.c` 时暴露，
> 而不是等到别人 include 时才炸）。

## 每层能 include 什么

| 层 | 允许 | 禁止 |
|---|---|---|
| `Task/` | 自己的、`Operation/Inc`、`Device/Inc`（**仅组合根**）、FreeRTOS、`project_config.h` | 直接 include HAL |
| `Operation/` | 自己的、`Common/Inc`、`project_config.h`、C 标准库 | **HAL / FreeRTOS / `Device/Inc` / 任何 `bsp_*`** |
| `Device/` | 自己的、`Common/Inc`、HAL、FreeRTOS、`board_config.h` | 业务逻辑 |
| `Common/` | **只有 C 标准库** | 任何一层（含 `project_config.h`） |

> `Operation/` 的禁令**由 CMake 强制**（拿不到那些 include 路径），不是靠自觉。
> 细则见 `01_工程分层架构.md` §强制表。

## 头文件里不做什么

| 不做 | 为什么 |
|---|---|
| **不在 `.h` 里定义变量** | 多个 `.c` include 会重复定义（链接期报错）。要共享就 `extern` 声明 + 一个 `.c` 里定义 |
| **不在 `.h` 里写实现**（除 `static inline` 的极短访问器） | 破坏"接口/实现分离"；改一行触发全工程重编 |
| **不 include 不必要的头** | 每个多出来的 include 都会传染给所有消费者。用**前置声明**代替 |
| **不 `#include <stm32f4xx_hal.h>` 只为了拿一个类型** | 改用前置声明（见下） |

## 前置声明

只需要一个**指针或引用**时，前置声明优于 include：

```c
/* 好：只知道有这个类型就够了 */
struct _UART_HandleTypeDef;
void bsp_uart_attach(struct _UART_HandleTypeDef *huart);

/* 差：为了一个指针把整个 HAL 拉进每个消费者 */
#include "stm32f4xx_hal.h"
void bsp_uart_attach(UART_HandleTypeDef *huart);
```

⚠️ **例外**：`Operation/` 层**不前置声明任何 HAL 类型** —— 那等于绕开了规矩 2。
`Operation/` 的接口里只能出现 C 标准类型与本层的 `typedef`。

## `static inline` 的使用边界

`.h` 里**只允许**这两类 `static inline`：

1. 一行能写完的取值/转换（`static inline uint8_t bsp_pin_mask(uint8_t pin) { ... }`）；
2. 编译期断言辅助。

超过 3 行的**一律**放 `.c`。

## 编译期断言

配置类宏的一致性检查放 `.h`，用 `#error` 而不是 `_Static_assert` ——
原因是它要在**配置错的那一刻**就喊，而且信息要能写成人话：

```c
#if (BOARD_HSE_VALUE != HSE_VALUE)
#error "board_config.h 的 BOARD_HSE_VALUE 与 stm32f4xx_hal_conf.h 的 HSE_VALUE 不一致"
#endif
```
