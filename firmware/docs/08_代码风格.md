# 08 — 代码风格

> 状态：**已定稿**（2026-09-21）
>
> **权威不是本文，是工程根的 `.clang-format`。** 本文只解释"为什么这么定"，
> 以及那几项机器管不了的约定。

## 管什么

缩进、括号、行宽、对齐 —— 这些**格式化工具能管的**事。

## 一句话规则

**不要手调格式。** 写完跑一次：

```bash
clang-format -i <你改过的文件>
```

`.clang-format` 在工程根，`clang-format` 会自动找到它。争议一律以工具输出为准。

## `.clang-format` 的关键设置（摘自工程根，不重复全文）

| 项 | 值 | 为什么 |
|---|---|---|
| `BasedOnStyle` | `LLVM` | 最常见的基线，跨项目互抄片段不会突兀 |
| `IndentWidth` / `TabWidth` | 4 / 4 | 4 空格缩进，**不用 Tab** |
| `UseTab` | `Never` | Tab 在不同编辑器里宽度不一，diff 会假性变大 |
| `ColumnLimit` | 88 | 窄列宽：并排看两个文件不用横向滚动 |
| `PointerAlignment` | `Left` | `int *p` 而不是 `int* p` —— 与 ST HAL 的写法一致 |
| `BreakBeforeBraces` | `Attach` | `if (x) {` 不换行 |
| `AllowShortIfStatementsOnASingleLine` | `false` | 便于打断点，也便于看清控制流 |
| `SortIncludes` / `IncludeBlocks` | `true` / `Regroup` | 见 `03` 的四段式 |
| `IndentCaseLabels` | `false` | `case` 与 `switch` 平齐一层 |
| `AlignConsecutiveDeclarations` | `true` | 一组声明对齐，扫读快 |
| `AlignConsecutiveAssignments` | `false` | 对齐 `=` 会在改动一行时产生大 diff |

⚠️ **`ColumnLimit: 88` 与 ST HAL 的代码冲突** —— HAL 里大量行超过 88 列。
所以**不要对 `Drivers/` 跑 clang-format**（那是只读第三方代码）。

## 机器管不了的三条

### 1. 函数长度

**超过 ~60 行的函数要考虑拆。** 判据不是行数，是"这一段能不能起个名字"。
能起名字就拆出来 —— 拆出来的函数名本身就是注释。

### 2. 嵌套深度

**`if` / `for` / `while` 嵌套不超过 4 层。** 超了用**提前返回**压平：

```c
/* ❌ 差 */
if (huart != NULL) {
    if (len > 0U) {
        if (HAL_UART_Transmit(...) == HAL_OK) {
            if (s_inited) { ... }
        }
    }
}

/* ✅ 好 */
if (huart == NULL)  { return BSP_ERR_NULL; }
if (len == 0U)      { return BSP_ERR_PARAM; }
if (!s_inited)      { return BSP_ERR_NOT_INIT; }
/* 主逻辑在零缩进层 */
```

### 3. 每行一件事

`a = b = c = 0;` 这类链式赋值、`i++, j--;` 这类逗号表达式 —— 一行一个。

## 命名与格式的分工

- **格式**（缩进/括号/对齐/行宽）→ `.clang-format`，机器管。
- **命名**（前缀/后缀/缩写）→ `04_命名规则.md`，clang-format 管不了。

## 编辑器怎么对齐

`.editorconfig` 在工程根，VS Code / CLion / Vim 会自动读它。
它与 `.clang-format` 保持一致（4 空格、UTF-8、文件末尾换行、去行尾空格）。

⚠️ **`.md` 文件例外**：`trim_trailing_whitespace = false` —— Markdown 里
行尾两个空格是**换行**语义，去掉会改变渲染结果。
