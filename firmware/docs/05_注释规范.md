# 05 — 注释规范

> 状态：**已定稿**（2026-09-21）
>
> 权威来源：参考工程 `template/AGENTS.md` §6.5（注释纪律），三条全采纳。

## 管什么

注释写什么、不写什么、哪些写法被禁止。

## 一条总原则

**注释写"为什么"，不写"做了什么"。** 后者看代码就有，前者看代码看不出来。

| 写 | 不写 |
|---|---|
| 为什么这么写、约束是什么 | 这行代码在做什么（`把 pin 置 1`） |
| 不这么写会怎样 | 函数名的同义复述 |
| 这个魔数的来历 | `/* 循环 10 次 */` |
| 踩过的坑（一行结论 + 指针） | 完整案情复盘 |

## 禁止引用行号

**注释与文档里禁止引用源码的行号**，无论那份源码是 `Drivers/` 下的第三方，
还是 `Core/` 下的 CubeMX 生成物。一律写**符号名**：

| ❌ 不要写 | ✅ 写成 |
|---|---|
| `stm32f4xx_hal_uart.c:1716` | `HAL_UART_Transmit_DMA 对 TxXferCount 的透传` |
| `port.c:161` | `uxCriticalNesting 的初值` |
| `main.c:80` | `MX_FREERTOS_Init()` 里 `osKernelInitialize()` 的调用点 |

**为什么**：行号是**静默的谎言**。升级 HAL、或 CubeMX 重新生成之后，被引用的行会挪位置，
而注释不报错、不告警、不让构建失败 —— 只有下一个照着它去查的人会扑空。
符号名则永远可以 `grep`。

> 这条在本工程**没有工具兜底**（参考工程曾有 `check_layering.py` 的 R7 检查，已删）。
> 也就是说：违反了不会有任何提示。正因为它没有兜底，反而更值得遵守。

### 三类例外（"看着像行号、但不算违规"）

1. **编译器 / 工具的输出原文** —— 例如 `Core/Src/main.c:47:10: fatal error: ...`。
   那是"当时跑出来的记录"，不是"指路坐标"，删掉反而失去证据。
2. **讲这条规则本身的示例**（就是上面那张表）。
3. **`docs/archive/` 下的历史快照** —— 那是决策链，不追溯修改。

## 注释体内不要出现 `/*`

例如描述路径写成 `Core/Src/*.c` 会触发 `-Wcomment`，
而且这个告警会从**别的编译单元**炸出来（见 `08` 与 `11`）。

**写法**：描述路径写成"`Core/Src` 下的全部 .c"，或加空格 `Core/Src/ * .c`。

## 事故战史怎么写

只留**一行结论 + 指针**，指向 `docs/` 里的文档或 `.workbuddy-ai/memory/`。
完整案情不要贴进生产代码 —— 代码里需要的是"别再犯"，不是"当年怎么犯的"。

```c
/* ⚠️ RTT 上行缓冲默认 1024 B 且满则丢：批量输出必须分块让路。
 * 详情见 docs/11 §RTT 丢数据。 */
```

## TODO 的写法

```c
/* TODO(funiang): 补 MspInit 里的引脚复用 —— 字段抄 CubeMX 生成物 */
```

- 必须带**具体做什么**，不能只写 `TODO`。
- 可选带负责人。
- ⚠️ TODO **不算实现**：交付时不能拿"写了 TODO"当"功能完成"（见 `AGENTS.md` §交付口径）。

## 存量注释不做一次性大清洗

老注释里的历史叙述**保留原样**。只在新写注释时执行本节规范，顺手遇到再改。

一次性重写存量注释成本高，而且极易引入新错误 —— 那是"为了整洁而制造风险"。

## 与 `template/` 的差异

`template/` 的注释里有大量"2026-09-xx 实测踩到…"的长叙述。本工程**不跟随**这种密度：
- 长叙述进 `docs/` 或 `.workbuddy-ai/memory/`，代码里只留一行结论 + 指针；
- 理由是那些叙述会随代码演进变成误导，而且它们本身在 `docs/00` 的溯源里已经有了。
