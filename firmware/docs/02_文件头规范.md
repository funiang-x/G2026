# 02 — 文件头规范

> 状态：**已定稿**（2026-09-21）
>
> 权威来源：参考工程 `template/` 的 21 个 `.c`/`.h` 实际写法（统计见文末证据）。

## 管什么

每个 `.c` / `.h` 文件顶部的注释块。

## 格式（照抄）

```c
/* ============================================================================
 *  bsp_uart.h —— UART 收发的设备层接口
 *
 *  本文件是 Device 层，**允许**出现 HAL 与 FreeRTOS。
 *  中断里只投事件、不跑业务（见 AGENTS.md §2 R3）。
 *
 *  ⚠️ 收满一帧才投递；单字节事件会淹没 Task 层。
 * ==========================================================================*/
#ifndef BSP_UART_H
#define BSP_UART_H
```

### 字段顺序（固定）

1. **第一行**：`文件名 —— 一句话说明这个文件干什么`（全角破折号 `—` / `——`）
2. **分层声明**：这个文件属于哪层、允许出现什么（`Device/` 的文件必写）
3. **补充说明**：为什么这么做 / 有什么约束 / 上层怎么用
4. **`⚠️` 重要约束**：会让下一个人踩坑的事，一行一条

### 硬性约定

| 约定 | 说明 |
|---|---|
| 用 `/* ... */` 块注释，不用 `//` 行注释堆叠 | 与 `.clang-format` 的 `-Wcomment` 检查相容 |
| 宽度控制在 80 列内 | 分隔线拉满 76 个 `=` |
| **不写** `@author` / `@date` / 修改记录 | 修改历史交给 git；写了必然过时 |
| **不写** Doxygen `@file` / `@brief` 标签 | 本工程不用 Doxygen，标签只是噪音 |
| 分隔线用 `===` 拉满，不用 `---` | 与 `board_config.h` / `project_config.h` 一致 |
| ⚠️ 注释体内**不要出现 `/*`** | 例如写路径 `Core/Src/*.c` 会触发 `-Wcomment`，且告警会从**别的编译单元**炸出来 |

### `.h` 与 `.c` 的差别

- `.h`：必须有文件头（它是接口，是别人读的第一眼）。
- `.c`：**必须有**，但可以短 —— 只写"这个文件实现什么 + 有什么非显然的约束"。
  纯转发/纯样板实现可以不写文件头。

### include guard 用哪种

| 位置 | 用什么 | 为什么 |
|---|---|---|
| 本工程自写的 `.h` | **`#ifndef` 宏**（`#ifndef BSP_UART_H`） | 与 ST HAL / CubeMX 生成物一致，全工程统一 |
| 参考工程 `template/` | `#pragma once` | 那是它的选择，本工程不跟随 —— **两个工程混抄时注意这一条** |

> ⚠️ 这条是本工程与 `template/` 的**有意分歧**：`template/` 用 `#pragma once`，
> 本工程用 `#ifndef` 宏。理由：本工程 `Core/Inc/` 下混着 CubeMX 生成的头（用 `#ifndef`），
> 统一成一种能减少"这个文件是生成的还是手写的"这类误判。
